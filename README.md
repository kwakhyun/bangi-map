# 방이2동 3D 생활지도

서울 송파구 방이2동을 실제 행정동 경계와 건물 외곽으로 탐색하는 3D GIS 웹서비스의 소스입니다.

**2026-10-29 운영을 종료했습니다.** NCP 서버, 공인 IP, 디스크와 전용 네트워크를 삭제하고 자동 배포를 해제했습니다. GitHub 소스와 로컬 비공개 DB 백업은 보존합니다. 마지막 운영 버전은 0.6.2입니다. [운영 종료 기록](docs/운영_종료.md)을 참고하세요.

## 구현된 기능

아래는 종료 전 구현 범위입니다. 현재 접속 가능한 배포 서비스는 없으며, 서버의 따릉이/주차 현황 수집도 중단됐습니다. 저장소의 시설과 공간 데이터, 검증 화면은 당시 스냅샷입니다.

- 브이월드 공식 무료 3D API의 실제 외벽 사진과 지붕 모형, 실사/기본 지도 전환, 경계와 시설 표식
- SGIS 원자료를 가공한 2026-07-01 경계, Overture 2026-09-23.1 건물 1,484개와 도로 404개, 공원 6곳과 학교 부지 1곳
- 원본 높이 646개, 층수로 높이를 추정한 10개, 높이가 없어 평면으로 표시하는 828개를 명확히 구분
- 3D/상부 시점 전환, 건물 선택과 출처 확인, 높이별 색상, 참고 그림자, 직선거리 측정, 배경지도, 모바일 하단 목록
- 경계 안 생활시설 30곳: 따릉이 3곳, 주차장 15곳, 화장실 12곳. ‘주변 포함’에서 기존 생활권 165곳 탐색
- 따릉이 2분 간격, 제공되는 주차 현황 5분 간격 수집. 미제공, 0대/0면, 오래된 값을 구분
- 실시간 주차 잔여면 연동 3곳은 방이2동 밖에 있으므로 ‘주변’ 표시. 방이2동 내 주차장 15곳의 잔여면은 당시 미제공
- 장소 저장, 길찾기, 익명 제보와 사진, 비공개 접수 조회, 운영자 처리와 답변

실사 지도는 브이월드 제공 모형입니다. 공식 구축표의 서울 지역 구축연도는 2024년이며 건물별 촬영일과 전체 누락률은 미확인입니다. 2025년 S-Map 비교 링크와 건물별 점검 목록을 제공합니다. [누락과 시점 점검 결과](docs/방이2동_실사데이터_누락과시점_점검.md)를 참고하세요. 건물 속성은 Overture 외곽과 위치를 대조하며, 실사 모형과 동일한 건물 ID를 사용하지 않습니다. 기본 지도의 건물 높이는 지도 속성으로 실측 정확도가 검증되지 않았습니다. 기본 지도 지면은 평탄한 WGS84 기준면이고 실제 외벽, 지붕, 지형 고도를 재현하지 않습니다. 그림자는 건물에서 기준면에 떨어지는 참고 표현으로 일조권 분석에 사용할 수 없습니다. 실제 데이터의 누락이 있을 수 있으며, 모든 건물을 완전하게 수록했다는 뜻은 아닙니다. 출처와 라이선스는 [공간 데이터 안내](data/bangi2/SOURCES.md)에 있습니다.

## 실행

Node 22.12 이상, Java 17, 실행 중인 Docker, Python 3, curl과 ripgrep(`rg`)이 필요합니다. Maven은 래퍼가 처음 실행할 때 내려받습니다.

공개 저장소에는 소스, 가공 공개 데이터와 검증 결과를 포함합니다. `.runtime/`, `.tools/`, 실제 API 키, 인증서 개인키, 관리자 비밀번호, DB 백업, 계정/보안 설정 화면은 제외합니다. 아래 로컬 전용 계정은 데모용이며 NCP 계정과 다릅니다. 기본 지도 실행에는 외부 API 키가 필요 없으며, 실시간 수집이나 실사 지도를 연결할 때 자신의 비공개 설정과 API 키를 준비해야 합니다.

```sh
npm ci
FIELDTWIN_DOCKER_CONTEXT="$(docker context show)" bash scripts/local-db.sh
npm run dev
```

- 접속: http://127.0.0.1:5173
- 로컬 운영자: `admin@bangi.local` / `BangiLocal!2026` (로컬 환경에서만 생성)
- 웹/API 종료: `npm run stop` (DB는 유지)
- DB 종료: `docker --context "$(docker context show)" stop fieldtwin-db` (생성할 때 선택한 Docker context 사용, 데이터 볼륨은 유지)
- 로컬 배포용 빌드: `npm run package`, 빌드 결과 실행: `npm start` (NCP 배포 명령이 아님)

DB 스크립트의 기본 context는 작성자 환경의 `colima-fieldtwin`이므로 위 예제에서는 현재 Docker context를 명시합니다. 새 DB는 저장소의 Flyway 마이그레이션으로 초기화되며, 비공개 운영 DB 백업 없이 실행할 수 있습니다. [실행과 재구축 안내](docs/운영.md)를 참고하세요.

서울시 키는 `.runtime/bangi/seoul.env`에서 로드합니다. `SEOUL_API_KEY`와 `SEOUL_BIKE_API_BASE`를 서버 환경값으로만 전달합니다. 키가 없어도 공개 시설 탐색과 제보를 이용할 수 있습니다. 키를 코드, 이미지, 브라우저 환경변수에 포함하지 않습니다.

## 운영 종료와 검증 워크플로

기존 NCP 스테이징과 `https://localhost:8443` 접속 환경은 종료했습니다. 기존 IP는 반납했으므로 배포 또는 SSH 접속 대상으로 다시 사용하지 마세요. 재개하려면 새 인프라와 인증 설정을 준비해야 합니다.

GitHub Actions의 푸시/PR 자동 실행 트리거와 이미지 패키징, NCP 배포 작업을 제거했습니다. 수동 검증 작업만 코드에 보존했고, GitHub의 해당 워크플로도 비활성화했습니다. `main`에 푸시해도 배포하지 않습니다. [이전 자동 배포 구성과 복구 절차](docs/CI_CD.md)는 과거 운영 기록으로 남깁니다.

## 실사 지도 설정

종료 전 브이월드 개발키 설정은 `.runtime/vworld/config.json`(600)에 보관했습니다. 당시 등록 URL은 `https://localhost:8443`, 키 만료일은 **2027-04-11**이었습니다. 기존 키의 폐기 여부와 유효성은 재개 전에 제공처에서 확인해야 합니다. 서울시 서버용 키와 다르게 브이월드 키는 브라우저 SDK 요청에서 보이는 키입니다. 저장소와 Docker 이미지에는 포함하지 않습니다. `node scripts/prepare-vworld3d.mjs`로 생성한 런타임 파일만 서버의 비공개 볼륨에 전달합니다. 일반 HTTP 로컬 개발에서는 기본 지도를 사용합니다.

종료 전에는 `infra/single-vm/compose.vworld.yaml`로 실사 SDK 런타임 설정을 연결했습니다. 이 파일과 관련 스크립트는 과거 배포 구성으로 보존하며, 기존 인증서나 서버가 남아 있다고 전제해 실행하면 안 됩니다. 설정 요건은 [실사 지도 어댑터 안내](experiments/vworld3d/README.md), 당시 데이터 선택 근거는 [무료 데이터 조사](docs/방이2동_실사3D_데이터조사.md)를 참고하세요.

## 검증

```sh
bash scripts/mvn.sh test -q -DargLine=-Djava.awt.headless=true
npm run typecheck
npm run build
node --test tests/vworld3d.test.mjs
npm run test:api # 로컬 API 실행 후
```

`tests/browser/platform.spec.ts`는 브라우저 회귀 테스트입니다. 실제 Chrome 화면과 반응형 검증 기록은 `evidence/`에 보존합니다. [0.6.2 배포 검증 기록](docs/배포_0.6.2.md)과 [0.5.0 검증 기록](docs/검증_결과.md)은 각 검증일의 결과이며 현재 실행 상태를 뜻하지 않습니다.

## 구조

- `apps/web`: React, TypeScript, TanStack Query, Cesium 3D GIS
- `services/api`: Java 17, Spring Boot, PostGIS 검색, 운영자 인증, 제보, 데이터 수집
- `data`: 정규화한 공개 시설 스냅샷과 원본 해시
- `infra/single-vm`: 종료 전 NCP 단일 서버의 Compose 구성
- `docs`: 실행/재구축 안내, 서비스 기획, 과거 운영과 검증 기록

시설 조회, 지도 설정, 제보 처리는 백엔드의 `places`, `map`, `reports` 패키지로 분리했습니다. 프런트엔드의 탐색 조회/필터 훅과 상세 패널은 `apps/web/src/features/explore`에 있습니다. 변경 범위, 검증 방법, 확장 전 남은 과제는 [구조 점검과 리팩터링](docs/구조_점검과_리팩터링.md)을 참고하세요. 2026-10-13 NCP 0.6.2에 반영하고 주요 기능을 검증했습니다. [배포 결과와 복구 절차](docs/배포_0.6.2.md)에 기록했습니다.

기존 Java 패키지와 컨테이너 이름의 `fieldtwin`은 코드와 마이그레이션 호환성을 위해 유지합니다. 공간 데이터 재생성은 원자료와 GIS Python 환경을 별도로 준비한 뒤 `scripts/import-bangi2.py`, `scripts/enrich-bangi2-context.py` 순서로 수행합니다. 작성자의 `.runtime/` 원본과 `.tools/gis-venv/`는 공개 저장소에 없으므로 복제만으로 이 재생성 환경이 준비되지는 않습니다. 가공 데이터는 저장소에 포함되어 기본 지도 실행에는 원자료 재수집이 필요 없습니다. 배포 이력이 있는 V1–V8 마이그레이션은 수정하지 말고 갱신 시 새 버전을 추가합니다.

이전 FieldTwin 소스 아카이브와 운영 DB 백업은 작성자의 로컬 비공개 보관물이며 공개 저장소에 포함되지 않습니다.
