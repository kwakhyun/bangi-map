# 리팩터링 0.6.2 NCP 배포

2026-10-13 KST, 기존 NCP Micro 서버의 웹과 API를 0.6.2로 교체했다. 시설 조회, 지도 설정, 제보 처리의 백엔드 분리와 탐색 훅/상세 패널의 프런트엔드 분리를 반영했다. 제보는 요청 키별 잠금과 JVM당 사진 변환 1개 제한을 사용한다.

접속은 기존과 같은 [https://localhost:8443](https://localhost:8443)이며 이 Mac의 SSH 터널을 사용한다. Chrome에 실사 지도 화면을 열어 두었다. 새 클라우드 자원, API 키, 공개 포트, 인증서 신뢰를 추가하지 않았다.

## 적용 범위

| 항목 | 이전 | 현재 |
|---|---|---|
| 웹 | `fieldtwin-web:0.6.1` | `fieldtwin-web:0.6.2` |
| API | `fieldtwin-api:0.5.0` | `fieldtwin-api:0.6.2` |
| DB | `fieldtwin-postgres:0.2.0` | 동일 컨테이너 유지 |
| DB 마이그레이션 | V1–V8 | 체크섬 동일, 신규 실행 없음 |
| 실사 지도 | 기존 브이월드 SDK와 런타임 키 | 유지 |

linux/amd64 이미지를 로컬에서 빌드했다. 서버로 전송한 압축 아카이브의 SHA-256은 `46675dbb95fa4c91ee4610ea512e6a12f8424722e3773888311ffed9fc7aa8c7`이며 전송 후 일치를 확인했다. 서버의 전송용 아카이브만 제거했고 로컬 아카이브, 이전 이미지, 복구 설정을 보관한다.

웹과 API를 중지한 뒤 함께 교체했다. 두 API 버전의 서로 다른 제보 잠금이 동시에 동작하지 않으며 1GB 서버에서 두 JVM이 겹쳐 실행되지 않는다. 교체 중 잠시 접속이 중단됐고 정상 기동 후 아래 검증을 수행했다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| NCP HTTPS API 회귀 테스트 | 8개 통과, 실패 0개 |
| 공개 시설과 공간 조회 | 기본 30곳, 주변 165곳, 주차장 33곳, 건물 1,484개 확인 |
| 사진 제보 | 이미지 정규화, 비공개 조회, 중복 재시도, 충돌과 잘못된 사진 거부 확인 |
| 운영자 처리 | 로그인, 사진 조회, CSRF, 수정 충돌, 완료 답변, 로그아웃 확인 |
| 기존 데이터 보존 | 시설/건물/경계 내용 해시, 기존 제보 6건, 사용자 1명, 마이그레이션 체크섬 일치 |
| TLS와 정적 파일 | 전용 CA 검증 성공, 배포 JS/CSS/GIS/점검 CSV/JSON 바이트 일치 |
| 브라우저 보안 설정 | 상위 페이지 CSP, SDK 문서의 분리된 CSP, 무인증 운영자 API 401 확인 |
| 데이터 수집 | 따릉이 READY, 주차 READY. 신규 API 기동 뒤 실제 수집 성공 시각 확인 |
| Chrome 데스크톱 | 실사 외벽/지붕, 기본 GIS 전환, 사보이 건물 검색/상세, 가까운 시설, 주변/연동 주차장 필터, 출처 안내 확인 |
| Chrome 모바일 크기 | 390×844에서 시설 상세와 잔여면, 길찾기 버튼, 지도 표시 확인 |
| 배포 전 로컬 검증 | 웹 빌드/타입 검사, Java 단위 테스트 22개, VWorld 테스트 3개 통과 |

API 회귀 테스트는 실제 시설 문제로 오인하지 않도록 명시한 합성 제보 1건을 만들었다. 사진 조회와 운영자 답변까지 검증하고 `RESOLVED`, 버전 3으로 완료 처리했다. 기존 6건과 함께 총 7건이며 감사 기록을 보존했다.

직전 리팩터링에서 PostgreSQL 동시성 통합 테스트 3개를 포함한 Java 테스트 25개가 통과했다. 이번 배포 전 재검사는 해당 통합 테스트 3개를 건너뛰었으며 NCP 운영 DB에서 병렬 부하 테스트를 실행하지 않았다. GitHub CI, 장시간 부하, 실제 휴대폰 GPU 성능은 이번 검증 범위에 포함되지 않는다.

DB 마이그레이션이 없는 앱 배포이며 이번 작업에서 새 전체 DB 백업을 만들지는 않았다. 배포 전후 데이터 해시와 개수를 비교했고 DB 컨테이너를 재생성하지 않았다. 원본 자료의 실사 누락률과 건물별 촬영일은 기존처럼 미확인이다.

## 서버 상태

검증 후 web/API/DB 모두 실행 중, 재시작 0회, OOM 없음이다. API 약 194MiB/320MiB, 웹 약 5MiB/64MiB, DB 약 84MiB/256MiB다. 호스트 가용 메모리는 281MiB, swap 사용은 188MiB/511MiB, 디스크 여유는 약 1.9GiB다. 이는 기능 검증 직후의 관측값이며 지속 부하 성능을 보장하는 수치는 아니다.

DB 컨테이너 ID는 배포 전후 `5230f23b54027fe287292bf6fc1fa505f25bf9415bf54572ff81174150d0143d`로 동일하다.

## 복구

로컬에서 아래 명령으로 직전 웹 0.6.1/API 0.5.0으로 복귀할 수 있다. 기존 DB와 제보 기록을 유지한다.

```sh
ssh -F .runtime/ncp/ssh_config fieldtwin-staging \
  'bash /opt/fieldtwin/rollback-app-20261013-031847/restore.sh'
```

배포 스크립트 `scripts/upgrade-app.sh`는 기동 또는 HTTPS 검증 실패 시 해당 복구 스크립트를 실행한다. 이번 배포는 정상 종료되어 자동/수동 복구를 실제로 실행하지 않았다. 복구 후에는 TLS 응답, Docker 이미지 태그와 실행 상태, 시설 검색 및 운영자 기능을 확인한다.

`scripts/verify-vworld-staging.mjs`는 현재 로컬 빌드와 서버 파일을 비교하는 배포 검증 도구다. 이전 빌드로 복구한 뒤 그대로 실행하면 자산 비교가 실패한다. 이전 0.5.0 API의 `/api/config.version`도 이미지 태그와 다르게 보고하므로, 과거 버전 확인에는 실제 Docker 이미지 태그를 기준으로 사용한다.
