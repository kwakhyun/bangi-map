# 비공개 NCP 스테이징 운영

기존 NCP 무료 Micro 1 vCPU/1GB 서버와 기존 공인 IP를 재사용한다. 신규 유료 서버, NKS, NAT Gateway, 저장소를 만들지 않는다. 웹 포트는 서버 127.0.0.1:8443에만 바인딩하고, 기존 IP 제한 SSH를 통해 접근한다.

## 배포

기본 배포 경로는 `main` 푸시 → GitHub Actions 검증 → 이미지 빌드 → NCP 자동 교체다. NCP에서 HTTPS와 API 검증을 통과해야 Actions의 deploy 작업도 성공한다. 배포 실패 또는 중단 시 이전 설정으로 복원한다. 서버의 자동 배포 서비스, 일시 중지와 수동 복구 명령은 [CI/CD 운영 안내](CI_CD.md)에 있다. 아래는 수동 배포 및 DB 변경 시의 절차다.

1. 로컬 빌드/타입 검사/Java 단위 테스트/API 통합 검증을 수행한다.
2. DB 변경이 포함되면 `node scripts/backup-staging.mjs`로 승인된 로컬 비공개 백업과 임시 DB 복원 검증을 수행한다. DB 변경이 없는 앱 교체도 이전 이미지와 runtime 설정을 보관하고 데이터/스키마 상태를 배포 전후 비교한다. 정기 백업은 별도로 필요하다.
3. `RELEASE_TAG=0.6.2 bash scripts/build-images.sh` 또는 설치된 buildx로 linux/amd64 `fieldtwin-web:0.6.2`, `fieldtwin-api:0.6.2`를 빌드한다. 후속 릴리스에는 새 태그를 사용하며 기존 Postgres 이미지는 바꾸지 않는다.
4. `docker save … | gzip | ssh … 'gzip -d | docker load'`로 이미지를 전송한다.
5. 최초 전환에서만 `bash scripts/deploy-bangi.sh`로 이전 설정 보관, AI 종료, Flyway owner 마이그레이션, API 권한 제한, 앱 기동을 순서대로 수행한다.
6. readiness, 실제 시설 검색, 인증과 제보 처리, Chrome 화면, 메모리 및 OOM 상태를 확인한다.

실행 중인 서비스는 db, fieldtwin-api, web이다. 메모리 제한은 각각 256MiB, 320MiB, 64MiB다. API에 서울시 외부 수집용 outbound 네트워크를 연결한다. inbound 공개 범위를 확대하지 않는다.

DB 변경이 없는 후속 배포는 새 이미지 태그와 `scripts/upgrade-app.sh`를 서버에 전달한 뒤 `bash /opt/fieldtwin/scripts/upgrade-app.sh 0.6.2`를 실행한다. 스크립트는 `rollback-app-날짜/`에 이미지 참조와 실행 설정, `restore.sh`를 보관한다. 1GB 메모리와 제보 잠금 호환성을 위해 웹/API를 중지한 뒤 함께 교체하며 DB 컨테이너는 유지한다. HTTPS readiness와 API 버전 검증에 실패하면 이전 설정으로 자동 복귀한다. 접속 검증 후 API 회귀 테스트와 Chrome 검증도 수행한다.

DB 마이그레이션이 있는 릴리스에는 별도 검토한 `scripts/upgrade-bangi.sh` 경로를 사용한다. 최초 전환 스크립트 `deploy-bangi.sh`는 재실행을 차단한다. 현재 0.6.2는 V1–V8을 변경하지 않는 앱 교체다.

서버 설정과 기존 이미지 참조는 `/opt/fieldtwin/rollback-before-bangi`에 보관한다. 서버 인증키, 관리자 비밀번호, API 키, DB 백업은 저장소에 포함하지 않는다. 사용자 브라우저 경고를 우회하는 코드는 만들지 않는다.

## 장애 대응

`ssh -F .runtime/ncp/ssh_config fieldtwin-staging`으로 접속한다. 서버에서 `/opt/fieldtwin/dc ps`와 `logs --tail 100 fieldtwin-api`를 확인한다. 인증키 URL이 로그에 남지 않게 수집 오류는 정해진 메시지만 기록한다. `GET /api/map-config`의 bikeSource와 parkingSource 상태, lastAttemptAt, lastSuccessAt을 비교한다.

따릉이는 2분 주기로 전 페이지를 받은 뒤 한 트랜잭션으로 적용한다. 실패하면 기존 값의 checkedAt을 갱신하지 않는다. UI에서 10분 지난 값은 대여 가능 수량으로 표시하지 않는다. 시설 위치/운영시간 스냅샷의 정기 갱신은 아직 자동화하지 않았다.

## 롤백

현재 0.6.2를 직전 웹 0.6.1/API 0.5.0으로 되돌리는 명령은 서버에서 `bash /opt/fieldtwin/rollback-app-20261013-031847/restore.sh`다. DB와 제보 기록은 유지한다. 실행 후 HTTPS 응답과 이전 이미지의 기동 여부를 확인한다. 이번 정상 배포에서는 복구 명령을 실제 실행하지 않았다.

아래는 산업용 FieldTwin에서 생활지도 서비스로 처음 전환했을 때의 복구 절차다.

새 테이블은 기존 V1–V3 스키마와 계정을 변경하지 않는 추가 방식이다. 이전 서비스로 복귀하려면 새 API/web을 중지하고 보관한 Compose 및 runtime 설정을 원위치로 복원한다. `grant-bangi.sql`에서 회수한 기존 업무 테이블 CRUD 권한도 이전 권한 스크립트(로컬 소스 아카이브 안의 `scripts/database-roles.mjs`)로 복구한다. 이전 API/web/AI 이미지 태그로 다시 시작한다. 정상 롤백에 DB 삭제나 백업 덮어쓰기는 필요 없다.

오래된 이미지와 백업은 자동으로 지우지 않는다. 이미지 정리는 이전 버전 복구 가능성을 확인하고 태그를 지정해 수행한다. `docker system prune --volumes`는 사용하지 않는다.

## 남은 운영 과제

도메인과 공인 인증서, 외부 공개 서비스 심사, 자동 백업/주기적 복원, 모니터링 알림, 사진/제보 보존 및 삭제 정책은 다음 운영 단계다. 단일 Micro 서버이므로 고가용성이나 상용 운영 SLA를 보장하지 않는다. 공개 제보 속도 제한은 서버가 보는 요청자 기준이므로 현재 SSH 스테이징에서는 공유 한도다.


## 주차 현황과 HTTPS

주차 현황은 공식 `GetParkingInfo`의 송파구 응답을 5분마다 받아 시설 코드로 연결한다. `NOW_PRK_VHCL_CNT`는 주차 중인 차량 수다. 전체 주차면 `TPKCT`에서 빼서 잔여면을 계산한다. 현황 제공 플래그, 정수 값, 총면수 초과 여부, 미래 시각을 검증한다. 실패한 조회는 기존 제공 시각을 갱신하지 않는다. 도시데이터 `CUR_PRK_CNT`는 설명이 모호해 잔여면 계산에 사용하지 않는다.

이 Mac 사용자 키체인에는 사용자 승인으로 `Bangi Localhost CA`를 SSL 용도로 등록했다. CA의 critical nameConstraints는 localhost DNS 범위만 허용하고 모든 IP 이름을 제외한다. 서버 인증서 SAN은 localhost만 포함한다. 기존 서버 인증서에 대한 개별 신뢰는 제거했다. Chrome에 이전 경고가 남는 경우 앱을 완전히 종료한 뒤 다시 열면 새 신뢰가 적용된다. 경고 무시나 인증서 검증 비활성화 옵션을 사용하지 않는다.

- leaf 만료: 2027-01-09 12:01:18 UTC. CA 만료: 2027-10-11.
- CA 개인키는 로컬 `.runtime/ncp/deploy/tls-localhost/ca.key`에만 보관한다. 서버에는 전송하지 않는다.
- 서버 leaf/key는 `/opt/fieldtwin/runtime/tls/`에 있고 UID 101이 읽는 최소 권한을 유지한다.
- 갱신은 기존 CA로 localhost SAN의 leaf를 새로 서명하고 사전 검증한 뒤 교체한다. 파일 bind mount를 갱신하려면 web 컨테이너를 재생성해야 한다.
- 검증: `curl --cacert .runtime/ncp/deploy/tls/ca.crt https://localhost:8443/api/map-config`. `-k`는 사용하지 않는다.
- 공인 도메인/다른 기기의 신뢰까지 해결한 구성은 아니다. 현재 승인 범위인 Mac의 SSH 터널 접속을 위한 설정이다.

## 방이2동 3D GIS 0.5.0

V8은 `bangi_districts`, `bangi_buildings` 테이블과 GiST 인덱스를 추가하고, 런타임 API 역할에는 SELECT만 부여합니다. 데이터 파일과 DB는 같은 생성 스크립트에서 만들어집니다. 갱신 시 원본 해시와 높이 정책을 검증하고 새로운 마이그레이션 및 정적 파일 버전을 사용합니다.

0.5.0에서 0.4.0으로 롤백할 때는 `rollback-bangi-날짜/compose.env`의 이전 API/웹 이미지 참조를 복원하고 `./dc up -d fieldtwin-api web`을 실행합니다. V8의 추가 테이블은 남겨도 기존 0.4.0 API와 호환됩니다. 산업용 FieldTwin 초기 전환 롤백 절차와 구분합니다.

2026-10-11 사용자의 승인을 받아 관리자 SSH ACG를 당시 접속 IP 한 곳(/32)의 TCP 22로 제한했습니다. 실제 허용 주소는 비공개 운영 설정에서 관리합니다. 네트워크가 바뀌면 터널이 끊길 수 있습니다. NCP 콘솔의 myIp로 주소를 확인하고 사용자 승인 후 정확한 /32 규칙만 교체합니다. 전체 인터넷에 SSH를 개방하지 않습니다.

3D는 브라우저 GPU에서 렌더링합니다. 서버는 gzip 공간 파일 약 170KB와 API를 제공합니다. Cesium 번들 약 1.1MB(gzip)는 지연 로딩됩니다. Micro 서버 비용 증가는 없지만 클라이언트 GPU/네트워크 성능에 따른 차이가 있으며 실제 저사양 휴대폰의 프레임률은 별도 검증이 필요합니다.
