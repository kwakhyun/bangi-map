# 로컬 실행과 운영 재구축

2026-10-29 기존 NCP 스테이징 운영을 종료했다. 서버, 디스크, 공인 IP와 전용 네트워크는 삭제됐고 서버 배포 타이머와 GitHub 워크플로는 비활성화했다. 현재 서비스 접속 주소는 없다. 삭제 결과와 비공개 백업 보관 상태는 [운영 종료 기록](운영_종료.md)에 있다.

## 공개 소스로 로컬 실행

[README 실행 안내](../README.md#실행)에 따라 실행 중인 Docker context를 지정하고 DB를 시작한 뒤 `npm run dev`를 실행한다. Node 22.12 이상, Java 17, Docker, Python 3, curl과 ripgrep이 필요하다. Maven은 `scripts/mvn.sh`가 다운로드와 체크섬 검증을 수행한다.

- 기본 지도, 가공 공개 공간 데이터, 시설 검색과 제보 기능은 기존 NCP 서버나 운영 DB 백업 없이 실행할 수 있다. 새 DB는 Flyway 마이그레이션으로 초기화한다.
- 로컬 웹 주소는 `http://127.0.0.1:5173`이다. API는 `127.0.0.1:8080`, PostGIS는 `127.0.0.1:55432`를 사용한다.
- 로컬 데모 계정과 비밀번호는 README에 있으며 로컬 개발 전용이다. 실제 배포 환경에 복사하지 않는다. 설정 예시는 [`.env.example`](../.env.example)에 있다.
- `npm run stop`은 웹/API만 중지한다. DB는 생성에 사용한 Docker context에서 `docker stop fieldtwin-db`로 별도 중지한다. 볼륨을 삭제하지 않으면 저장한 데이터가 유지된다.
- `npm run package`와 `npm start`는 로컬 빌드/실행 명령이다. NCP에 자원을 만들거나 배포하지 않는다.

## 외부 데이터와 실사 지도

저장소의 시설/공간 데이터는 2026년 10월 개발 당시의 스냅샷이다. 시설 원자료 정기 갱신은 자동화하지 않았으며, NCP 종료 이후 서버의 실시간 수집도 중단됐다.

따릉이와 주차 현황을 새로 수집하려면 유효한 서울 열린데이터광장 키와 서버 설정이 필요하다. 로컬 실행기는 `.runtime/bangi/seoul.env`의 `SEOUL_API_KEY`, `SEOUL_BIKE_API_BASE`를 읽는다. 키가 없어도 정적 시설 탐색은 가능하고 실시간 수량은 제공되지 않는다. 공식 HTTP API 사용의 전송 위험과 과거 적용 조건은 [데이터 출처](../data/SOURCES.md)에 기록했다. 키를 브라우저 환경변수, 이미지, 로그에 포함하지 않는다.

수집기를 설정해 실행하면 따릉이는 2분, 주차는 5분 간격으로 갱신한다. 실패한 조회에서 기존 제공 시각을 갱신하지 않고, 10분 지난 수량은 최신 값으로 표시하지 않는다. 방이2동 내 주차장 15곳은 당시 잔여면 미제공이었고 연동된 주차장 3곳은 주변 지역에 있다. API 상태값은 [API 문서](API.md)에 있다.

기본 Cesium 지도에는 브이월드 키가 필요 없다. 실사 지도는 유효한 VWorld 키, 등록 origin과 일치하는 HTTPS 환경, SDK 런타임 설정이 필요하다. 작성자의 `.runtime/vworld/config.json`은 공개 저장소에 포함되지 않는다. [실사 지도 어댑터 안내](../experiments/vworld3d/README.md)를 참고한다.

## 남겨 둔 배포 구성의 범위

다음 파일은 종료 전 구현 기록이다. 기존 서버와 인증 자료에 의존하므로 새 저장소 복제 후 그대로 실행할 수 있는 프로비저닝 도구가 아니다.

| 파일/경로 | 보존 목적과 의존성 |
|---|---|
| `infra/single-vm/` | 단일 서버 Compose 구성. DB 역할, runtime 설정, TLS, 이미지와 볼륨을 별도 준비해야 함 |
| `scripts/deploy-bangi.sh`, `scripts/upgrade-bangi.sh` | 기존 FieldTwin DB에서 생활지도 서비스로 전환하거나 마이그레이션하는 과거 절차 |
| `scripts/upgrade-app.sh`, `scripts/upgrade-vworld.sh` | 준비된 기존 서버의 앱/SDK 교체와 롤백 절차 |
| `scripts/cicd/`, `infra/cicd/` | 과거 자동 배포 poller와 복구 코드. 서버 에이전트와 개인키는 서버 삭제로 제거됨 |
| `scripts/staging-tunnel.sh`, `scripts/backup-staging.mjs`, `scripts/verify-vworld-staging.mjs` | 삭제된 서버의 SSH 설정, 인증서와 비공개 runtime에 의존하는 과거 운영 도구 |
| `scripts/preview-vworld3d.mjs --app` | 과거 인증서와 8445 SSH 터널의 NCP API를 사용했던 검증 도구. 독립 로컬 실행기 아님 |

`main`에 푸시해도 테스트나 배포가 자동 실행되지 않는다. `.github/workflows/verify.yml`에는 수동 검증 작업만 남아 있고 GitHub에서 `disabled_manually` 상태다. 필요할 때 별도로 활성화해 실행해도 현재 파일에는 이미지 패키징이나 배포 작업이 없다. [CI/CD 기록](CI_CD.md)에 종료 전 설계와 복구 방식이 있다.

## 운영을 새로 시작할 때

1. 새 서버와 네트워크, 관리 접속 범위를 정한다. 반납한 공인 IP나 삭제된 SSH 설정을 재사용하지 않는다. 현재 저장소에는 새 클라우드 자원 생성 자동화가 없다.
2. 새 접속 인증키, DB 비밀번호/역할, 운영자 계정, TLS와 제공처 API 키를 준비한다. 과거 localhost 인증서와 키체인 신뢰가 남아 있다고 가정하지 않는다. 운영 종료 점검에서는 사용자/System 키체인에서 기존 CA를 찾지 못했다.
3. 신규 DB는 마이그레이션으로 초기화한다. 이전 사용자/제보를 이어갈 필요가 있을 때만 비공개 백업을 복원하고 데이터와 권한을 검증한다. 비밀번호 해시와 제보가 포함된 백업은 공개하지 않는다.
4. 새 환경에 맞게 이미지, Compose, origin, 수집기, 방화벽을 구성한다. 기존 Flyway V1–V8은 수정하지 않고 변경은 새 버전으로 추가한다.
5. 웹/API 테스트, 실제 브라우저, 데이터 출처/신선도, 인증/권한, HTTPS와 복원 절차를 검증한다. 자동 배포를 다시 만들 경우 현재 수동 워크플로에 패키징/배포 작업을 별도로 구현하고 새 callback 키 쌍과 에이전트를 준비해야 한다.

과거 단일 Micro 구성은 DB 256MiB, API 320MiB, 웹 64MiB 제한을 사용했다. 이는 당시 시험 환경의 설정이며 새 환경의 용량이나 성능을 보장하지 않는다. 공개 운영에는 도메인과 공인 인증서, 자동 백업/복원 점검, 장애 알림, 제보/사진 보존 정책, 모바일 성능과 접근성 검토가 남아 있다.
