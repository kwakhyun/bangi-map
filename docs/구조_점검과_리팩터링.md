# 구조 점검과 1차 리팩터링

확인일: 2026-10-13. 기존 화면과 HTTP 계약을 유지하며 변경 범위를 나눈다. 변경 사항은 웹/API 0.6.2로 기존 NCP Micro 서버에 배포했다. [배포 결과와 복구 절차](배포_0.6.2.md)에 실제 서버 검증을 기록했다.

## 우선순위와 처리 결과

단순 조회에는 비어 있는 Service를 추가하지 않았다. `PlaceSearch`와 제보 명령/접수 결과는 타입을 명시하되, 기존 JSON 필드와 오류 코드는 유지했다. 가변 JSON 응답을 모두 DTO로 바꾸는 작업은 후속으로 분리한다.

## 제보 동시성과 호환성

- `pg_advisory_xact_lock(731208, hashtext(requestKey))`를 사용한다. 커밋/롤백 때 해제되며 동일 키의 재시도만 기다린다. 해시 충돌 시 다른 키가 잠깐 직렬화될 수 있으나 접수 ID와 DB 유일 제약은 별도이므로 데이터가 합쳐지지 않는다.
- 원문 기반 요청 해시와 접수 토큰 해시 계산은 그대로여서 기존 접수 재시도를 지원한다.
- 같은 IP의 일일 한도는 DB 행의 원자적 증가와 트랜잭션으로 유지한다. 사진 오류와 중복 재시도는 한도를 소비하지 않는다.
- 전역 DB 잠금 제거 후 이미지 디코딩이 무제한 병렬 실행되지 않도록 JVM당 사진 변환을 1개로 제한한다. 사진 처리 중 추가 사진 요청은 429와 재시도 안내를 받고, 사진 없는 접수는 계속 진행한다. 실패 시 허용량도 반환된다. 현재 Micro 서버 메모리를 위한 제한이며 고용량 사진 처리 확장 시 별도 작업 큐로 분리할 수 있다.
- 운영자 처리와 감사 기록은 같은 트랜잭션이다. 감사 INSERT가 실패하면 처리 상태와 버전 변경도 롤백한다.
- API 경로, HTTP 권한/CSRF/Origin 검사, 비공개 접수 조회, 사진 정규화, 낙관적 수정 충돌 처리를 유지했다. DB 마이그레이션 V1–V8과 운영 데이터를 변경하지 않았다.

## 검증

- Java 테스트 25개 통과. 요청 키별 동시성 외에 사진 변환 용량 제한과 실패 후 용량 반환 검증도 포함한다. 실제 PostgreSQL 통합 테스트 3개는 서로 다른 접수의 동시 진행, 같은 접수의 중복 방지, 31개 동시 요청 중 최대 30개 허용, 감사 실패 시 롤백을 검사한다.
- 기존 HTTP API 회귀 테스트 8개 통과. 기록: `evidence/refactor-api-tests.tap`.
- TypeScript 타입 검사, 웹 프로덕션 빌드, Java JAR 패키징 통과.
- 브이월드 SDK 보안 경계 테스트 3개 통과. 실사 SDK 자체와 운영 키는 변경하지 않았다.
- Chrome에서 로컬 기본 지도의 건물 검색/상세, 시설 필터, 주변 전환과 빈 결과, 시설 상세, 출처 안내의 점검 자료 조회를 확인했다. 390×844 모바일에서도 지도와 건물 상세가 함께 표시된다. 키 없는 테스트 DB의 연동 주차장 0건은 정상이다.
- 검증 요약: `evidence/refactor-verification.json`. 화면 증거: `evidence/refactor-desktop.png`, `evidence/refactor-mobile.png`.
- CI 설정에 추가한 전체 파이프라인은 GitHub에서 아직 실행하지 않았다. 이번 로컬 Chrome 검증과 CI Playwright 실행은 구분한다.

PostgreSQL 테스트는 운영 DB 오접속을 막기 위해 아래 형식의 명시적인 로컬 DB에서만 실행된다. 환경변수가 없으면 3개 통합 테스트는 건너뛴다.

```sh
# 기존 로컬 PostGIS 컨테이너에 전용 DB를 만든 뒤 실행한다.
docker --context colima-fieldtwin exec fieldtwin-db createdb -U fieldtwin bangi_refactor_test
BANGI_TEST_DATABASE=jdbc:postgresql://127.0.0.1:55432/bangi_refactor_test \
  bash scripts/mvn.sh test -q -DargLine=-Djava.awt.headless=true
npm run typecheck
npm run build
node --test tests/vworld3d.test.mjs
```

## 후속 작업

1. **버전 혼합 방지:** NCP의 웹/API를 0.6.2로 교체했다. 이전 API를 중지한 다음 새 API를 기동해 서로 다른 잠금 구현이 겹치지 않게 했다. 이전 전역 잠금 버전과 새 요청별 잠금 버전을 혼합 운영하면 두 버전 사이 재시도가 기존과 다른 409 응답을 받을 수 있으므로 후속 배포에서도 피한다.
2. **다중 API 인스턴스 도입 전:** `BikeSync`/`ParkingSync`의 HTTP 수집 클라이언트, 파싱, 저장을 분리하고 작업 소유권/분산 잠금을 추가한다. 현재 인스턴스마다 스케줄이 실행되어 중복 외부 호출이 생긴다.
3. **탐색 기능 확대 시:** 남아 있는 App의 목록 UI와 선택 상태를 분리하고, Cesium Viewer의 생성/파괴와 레이어 갱신을 별도 훅/모듈로 옮긴다. 현재 렌더러의 효과 의존성과 이벤트 해제는 그대로 유지했다.
4. **다른 지역으로 확대 전:** 고정된 `bangi2` 경계와 중앙 좌표, API의 300건 제한, 전체 공간 JSON 로딩을 지역 설정과 범위 기반 조회로 전환한다. 단순 페이지 나누기만 하면 지도에서 시설이 조용히 누락될 수 있다.
5. **응답 계약 정비:** `Map<String,Object>`와 `Db` 공개 필드 의존성을 단계적으로 DTO/전용 저장소로 바꾼다. 대규모 ORM 전환은 현재 서버 자원과 요구사항에 비해 우선순위가 낮다.
6. **변경 이력:** 1차 리팩터링 당시 전체가 untracked 상태였다. 이후 사용자 요청으로 공개 저장소의 `main` 초기 커밋을 준비하며 `.runtime`/`.tools`, 인증 자료와 계정 화면을 제외하고 공개 파일을 점검했다. 후속 변경은 별도 커밋과 검증 기록으로 관리한다.

현재 단일 저사양 서버에서 K8S 또는 서비스 분할을 도입하는 것보다 위 경계와 검증을 정비하는 편이 운영 부담이 작다. 이번 변경은 추가 클라우드 자원을 만들지 않는다.
