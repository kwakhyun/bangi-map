# 방이2동 3D 생활지도 운영 종료

2026-10-29(KST), 사용자의 운영 종료 요청과 영구 삭제 승인에 따라 기존 NCP 스테이징을 철거했다. 소스와 로컬 비공개 백업은 보존했다.

## 삭제와 중지 결과

- `fieldtwin-staging-01` Micro 서버와 기본 10GB 디스크를 반납했다. 콘솔에서 Server 0, Storage 0을 확인했다.
- 서버에 연결했던 공인 IP를 함께 반납했다. 콘솔에서 Public IP 0을 확인했다. 반납한 IP를 접속 또는 배포 대상으로 재사용하면 안 된다.
- `fieldtwin-public`, `fieldtwin-lb-private`, `fieldtwin-nodes` 서브넷과 `fieldtwin-staging` VPC를 삭제했다. 기본 ACG, Network ACL, 공개/비공개 라우팅 테이블도 삭제됐다.
- NKS 클러스터, NAT Gateway, KMS 키, 추가 디스크, 스냅샷과 서버 이미지는 없었다.
- 후속 점검에서 KMS 서비스 이용 신청도 해지했고, Subscription 화면이 ‘상품 이용 신청’으로 전환된 것을 확인했다.
- 별도 프로젝트인 `twinpilot`의 네트워크와 인증키는 보존했다.
- GitHub `verify.yml` 워크플로를 비활성화하고 푸시/PR 트리거, 이미지 패키징과 NCP 배포 작업을 제거했다. 수동 검증 코드는 보존한다.
- 과거 성공한 GitHub Deployment 상태는 `inactive`로 변경했다. Actions와 배포 이력은 기록으로 남으며 운영 중인 서버를 뜻하지 않는다.
- 서버 반납 전에 `bangi-deploy.timer`를 비활성화하고 배포 서비스와 웹/API, DB 컨테이너를 정상 종료했다.
- 로컬 개발 서비스, SSH 터널, `fieldtwin` Colima는 실행 중이 아니었다. 반납된 서버의 로컬 SSH 설정, known_hosts 기록, 개인 인증키와 관리자 비밀번호 파일을 제거했다.

종료 전에 발생한 이용료나 정산 내역은 자원 반납으로 소급 취소되지 않는다. 이 기록은 자원 삭제 확인이며 최종 청구서 검증 결과는 아니다.

계정 전체 자원과 계약을 대조한 후속 점검에서도 과금 중인 인프라는 발견되지 않았다. 별도 프로젝트의 무료 네트워크 설정, 미사용 서버 인증키 등록과 계정 관리 항목은 남아 있으므로 계정의 모든 항목을 삭제했다는 뜻은 아니다. 비용 내역, 크레딧 잔액과 콘솔 화면은 비공개 자료로 보관하며 이 저장소에 게시하지 않는다.

## 남은 항목과 재개 조건

NCP의 미사용 서버 인증키 등록 항목 `fieldtwin-staging-key`는 삭제를 완료하지 못했다. 서버가 0대가 된 뒤 콘솔에서 ‘서버 관리 및 설정 변경 → 인증키 관리’ 메뉴가 표시되지 않았다. 기존 서버는 삭제됐고 로컬 개인키도 제거했지만, NCP 등록 항목의 삭제 여부를 완료로 기록하지 않는다. 새 서버를 만들어 해결하지 않았다.

서울시와 브이월드 등 외부 제공처의 API 키 발급 기록은 이번 NCP 철거에서 취소하지 않았다. 서버 삭제로 기존 수집과 지도 서비스의 호출은 종료됐다. 로컬 비공개 설정과 과거 배포 자료는 보존한다.

운영을 다시 시작하려면 새 인프라, 새 접속 인증키와 TLS 설정, 제공처 API 키의 상태를 준비해야 한다. 새 데이터로 시작할 때는 저장소의 마이그레이션으로 DB를 초기화하고, 기존 운영 데이터를 이어갈 때만 권한 있는 관리자가 비공개 백업을 복원한다. 기존 SSH 접속이나 자동 배포는 사용할 수 없다. [실행과 재구축 안내](운영.md)와 [과거 CI/CD 기록](CI_CD.md)을 구분해서 참고한다.
